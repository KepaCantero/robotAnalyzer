# El analizador, explicado fácil (ELI5)

Fecha: 2026-10-17. Este documento es el mapa para quien llega nuevo — incluido
un Kepa futuro que no recuerde nada. No es fuente de verdad (eso es el DOCX y
sus 156 reglas); es la explicación de por qué el sistema es como es, contada
como se le explica a alguien en la cocina con un café.

## ¿Qué es esto, en una frase

Un analista de fondos y ETFs que trabaja solo y sigue un manual escrito de
**156 reglas**: cada veredicto se puede trazar hasta una regla concreta y un
dato con etiqueta. Ni improvisa, ni opina por vibes, ni disfraza lo que no
sabe — cuando no sabe algo, lo dice en mayúsculas: `NO_DISPONIBLE`.

## Las cinco ideas que explican todo el sistema

### 1. Los cocineros cocinan; el inspector pone la nota (ADR-006)

Los agentes LLM son los cocineros: proponen factores ("la valoración de este
ETF me parece un 70"). El **motor determinista** es el inspector: coge esos
factores, aplica los pesos de un JSON (`curated/scoring-weights.json`) y
calcula el score. El cocinero no puede ponerse la nota a sí mismo.

- **Por qué:** si el LLM calculase el score, cada ejecución daría una
 distinta y nada sería auditable. Así, con los mismos factores y pesos, el
  resultado es siempre el mismo — y si no te gusta, cambias el JSON, no
  "re-entrenas" nada.
- **Regla práctica:** los pesos no se tocan en código; se editan en curated
  y se regenera.

### 2. Cada dato lleva su semáforo (reglas 75 y 101)

Ningún dato crítico viaja suelto: viaja con una etiqueta que dice cuánto
confiar en él.

| Etiqueta | Qué significa | Ejemplo |
|---|---|---|
| `VERIFICADO` | Lo dice la fuente directa | Precio de cierre de Yahoo/Stooq |
| `CALCULADO` | Derivado de datos verificados | Volatilidad anual, Sharpe (regla 75) |
| `ESTIMADO` | Supuesto declarado | Fair value de un índice |
| `INFERIDO` | Deducción, no dato | ISIN casado por nombre |
| `NO_DISPONIBLE` | No hay dato — y punto | Sin red, ticker sin respuesta |

Un ISIN no verificado vale `null`, jamás "parecido". Un ratio que no se puede
calcular (Sharpe de una serie plana) es `None`, no 0 — cero sería mentir con
número exacto.

### 3. La biblioteca y el cuaderno (grafo + bóveda, patrones fukura)

- `.semantic-graph/memory.json` es la **biblioteca**: fichas (temas,
  productos, análisis, fuentes, ADRs, contradicciones) con hilos entre ellas.
- `.semantic-graph/curated/*.json` son los **cajones que rellenas a mano**:
  pesos, semillas de universo, política de frescura. La biblioteca se
  reconstruye desde aquí — nunca se edita a mano.
- `boveda/` es el **cuaderno Obsidian** que se escribe solo para leerlo
  tranquilo. Read-only: si algo está mal, se corrige la fuente y se
  regenera.

Metabolismo: los datos caducan como la comida (TTL por tipo — un precio
caduca en 1 día, un TER en 30). Las observaciones `manual:*` de la biblioteca
sobreviven a las regeneraciones; por eso `memory.json` SÍ se commitea.

### 4. Dos vecinos, no uno (cadena de fuentes de mercado)

Para saber el precio del pan no preguntas a un solo vecino: preguntas a
Yahoo y, si no contesta o te cuelga el teléfono (429), a Stooq (CSV sin
clave). Si ninguno contesta, la respuesta es "no lo sé", con la traza de a
quién se preguntó — nunca un número inventado para rellenar el hueco. El
orden se cambia con `ANALIZADOR_FUENTES_MERCADO=stooq,yahoo`.

### 5. El abogado del diablo cobra por hacer dudar (red team, reglas 118-119)

Antes de publicar, un agente adversarial intenta **destruir** la tesis: qué
supuesto es débil, qué riesgo está subestimado, qué alternativa es mejor.
Y una verdad incómoda escrita en la propia metodología: **TOP 5 ≠
recomendación de compra** (regla 149). Puede (y debe) salir "no compraría
ninguno ahora".

## Recorrido de un análisis (qué pasa cuando escribes `analizar "minería de cobre"`)

1. **Interpretar** la temática y construir la tesis (reglas 2-4).
2. **Universo**: al menos 10 candidatos de varias categorías — si hay menos,
   se declara, no se rellena con humo (reglas 7-8).
3. **Datos**: cotización e histórico por la cadena de fuentes; métricas duras
   (volatilidad, drawdown, Sharpe, Sortino) calculadas en stdlib puro y
   etiquetadas `CALCULADO`.
4. **Factores**: los agentes puntúan 0-100 cada factor; las métricas duras
   alimentan `volatilidad_drawdown` aunque no haya LLM.
5. **Motor**: pesos por naturaleza, control de doble conteo (una métrica no
   cuenta dos veces, regla 63), penalizaciones, confianza por calidad de
   datos.
6. **TOP 5** con gates de publicación (pesos que suman 1.00, cero fichas
   huérfanas…): rojo = no se publica.
7. **Red team** y veredicto de compra.
8. **Publicar**: informe estándar, bóveda Obsidian, grafo, análisis
   versionado (regla 137: el ranking de hoy no borra el de ayer).

Sin clave de LLM todo esto **funciona igual** en modo determinista: los
juicios van en neutro y el informe lo declara — nada "parece" análisis real
sin serlo. Con LLM, los mismos pesos y el mismo motor.

## Por qué estas decisiones (y qué se rechazó)

Honestidad estilo ADR — cada decisión con su alternativa descartada:

| Decisión | Alternativa rechazada | Por qué |
|---|---|---|
| Score por código determinista | Que el LLM puntúe directo | Reproducible y auditable (ADR-006) |
| stdlib puro en el núcleo | pandas/QuantStats/QuantLib | Python 3.9 pelado en esta máquina; sin caja negra: 60 líneas de métricas legibles |
| Modo eco que se declara | Fallback silencioso a "estimaciones" | Regla 101: no inventar jamás |
| Cadena Yahoo→Stooq | Un solo proveedor | Yahoo 429 existe; Stooq sin clave responde |
| Curated en JSON | Editar el grafo a mano | El grafo se regenera; curated es la fuente |
| Observaciones `manual:*` en el grafo | Todo generado | La opinión humana explícita sobrevive a los re-syncs |

## Pruébalo en 30 segundos

```bash
# 1. Demo completa sin red (determinista, 2 segundos)
PYTHONPATH=src python3 -m analizador.cli demo

# 2. Análisis real de una temática (trabaja la cadena de fuentes)
PYTHONPATH=src python3 -m analizador.cli analizar "minería de cobre"

# 3. Los 63 tests
PYTHONPATH=src python3 -m unittest discover -s tests

# 4. Dashboard de backtesting + batería de tests
source .venv/bin/activate && streamlit run dashboard/app.py
```

## Dónde está la verdad de cada cosa

- Duda metodológica → **regla N del DOCX** (los prompts son su destilado).
- Duda de pesos/frescura/semilla → **`curated/*.json`**.
- Duda de arquitectura → **ADRs del grafo** (`adr:001`–`adr:007`) y
  `docs/02-arquitectura.md`.
- Duda de "¿por qué este patrón fukura sí y este no?" →
  `docs/01-evaluacion-patrones-fukura.md` (evaluación honesta, no fe).
